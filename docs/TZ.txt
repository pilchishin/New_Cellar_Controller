ТЕХНИЧЕСКОЕ ЗАДАНИЕ
Автоматический контроллер микроклимата погреба
================================================================================
Версия: 1.0
Основание: исходный код проекта New_Cellar_Controller-rewrite
Платформа: Arduino Nano (ATmega328P)

1. НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ
================================================================================

Устройство предназначено для автоматического поддержания оптимальных условий
хранения овощей в погребе путём управления приточной вентиляцией и проведением
периодического озонирования. Контроллер непрерывно отслеживает параметры
микроклимата внутри погреба и сравнивает их с параметрами наружного воздуха,
принимая решение о включении вентилятора на основании разницы абсолютного
содержания влаги в воздухе.

Устройство является автономным встраиваемым контроллером без сетевого
подключения. Все настройки выполняются через локальный пользовательский
интерфейс на базе ЖК-дисплея 16×2 и трёх кнопок.


2. ЦЕЛЕВЫЕ ПАРАМЕТРЫ МИКРОКЛИМАТА
================================================================================

  Целевая температура хранения   : 4.0 °C
  Целевая относительная влажность: 85 %
  Допустимое отклонение по T     : ± 0.5 °C (гистерезис включения)
  Допустимое отклонение по RH    : ± 3.0 % (гистерезис включения)
  Минимально допустимая T внутри : 2.0 °C (ниже — аварийная остановка)

  Диапазон уставки температуры   : 2.0 ... 15.0 °C (настраивается через меню)
  Диапазон уставки влажности     : 50 ... 95 % (настраивается через меню)


3. СОСТАВ АППАРАТНЫХ СРЕДСТВ
================================================================================

3.1. Микроконтроллер
  - Arduino Nano (ATmega328P, 16 МГц, 32 КБ Flash, 2 КБ RAM, 1 КБ EEPROM)

3.2. Датчики
  ┌───────────────────────────────────────────────────────────────────────────┐
  │ Датчик    │ Назначение            │ Интерфейс │ Адрес/Пин │ Параметры     │
  ├───────────────────────────────────────────────────────────────────────────┤
  │ BME280    │ T и RH внутри погреба │ I2C       │ 0x76      │ T, RH         │
  │ HTU21D    │ T и RH снаружи        │ I2C       │ авто      │ T, RH         │
  │ DS18B20   │ Контрольная T внутри  │ 1-Wire    │ D2        │ T (12 бит)    │

  - Кнопка ВНИЗ             : пин D4
  - Кнопка МЕНЮ/ВЫБОР       : пин D5

4. АЛГОРИТМ КЛИМАТ-КОНТРОЛЯ
================================================================================

4.1. Принцип работы

  Основой алгоритма является сравнение абсолютного содержания влаги (г/м³)
  внутри погреба и снаружи. Использование абсолютной влажности (AH) вместо
  относительной (RH) является обязательным требованием: RH зависит от
  температуры и не позволяет корректно оценить реальный перенос влаги
  при подаче холодного уличного воздуха в тёплый погреб.

4.2. Расчётные формулы

  Давление насыщенного пара (формула Магнуса-Тетенса, WMO):
    SVP = 6.112 × exp(17.62 × T / (243.12 + T))  [гПа]

  Абсолютная влажность:
    AH = 216.7 × (RH/100 × SVP) / (T + 273.15)   [г/м³]

  Точка росы:
    H   = ln(RH/100) + 17.62×T / (243.12+T)
    Td  = 243.12 × H / (17.62 − H)                [°C]

4.3. Логика принятия решения о вентиляции

  Вентилятор включается при выполнении ВСЕХ пяти условий:

  (A) ventilation_needed    — нужна вентиляция:
        is_too_hot   = T_in > (T_target + 0.5)    [при выключенном вентиляторе]
                       T_in > (T_target - 0.5)    [при включённом, гистерезис]
        is_too_humid = RH_in > (RH_target + 3.0)  [при выключенном]
                       RH_in > (RH_target - 3.0)  [при включённом, гистерезис]
        needed = is_too_hot OR is_too_humid

  (B) ventilation_is_effective — вентиляция даст эффект:
        (AH_out + 1.0) < AH_in
        (уличный воздух суше внутреннего не менее чем на 1 г/м³)

  (C) condensation_is_safe — нет риска конденсата на стенах:
        (Td_out + 2.0) < T_in
        (точка росы уличного воздуха + запас 2°C ниже температуры внутри)

  (D) freeze_safe — нет риска промерзания:
        T_out > 0.0 °C
        (не вентилировать при минусовой температуре на улице)

  (E) cooling_is_possible — охлаждение физически возможно:
        НЕ is_too_hot ИЛИ (T_out < T_in)
        (если сработал температурный триггер — уличный воздух должен быть холоднее)

  Вентилятор ВЫКЛЮЧАЕТСЯ если хотя бы одно из условий не выполняется.

4.4. Фильтрация показаний датчиков

  Для каждого измеряемого параметра применяется комбинированный фильтр:
    - Медианный фильтр (окно 3 отсчёта) — устранение выбросов
    - Экспоненциальное скользящее среднее EMA (α = 0.2) — сглаживание тренда

  Период опроса датчиков: 10 секунд.
  Данные считаются стабильными после 3 последовательных успешных чтений.


5. ЦИКЛ ОЗОНИРОВАНИЯ
================================================================================

5.1. Расписание

  Цикл запускается по расписанию, хранящемуся в RTC DS3231.
  По умолчанию: 1 раз в неделю (воскресенье, 02:00).
  Расписание настраивается через сервисное меню.

5.2. Условия запуска

  Цикл БЛОКИРУЕТСЯ при любом из условий:
    - Температура наружного воздуха T_out < 0 °C (риск промерзания канала)
    - Присутствие пользователя (активность кнопок в течение последних 30 секунд)

  При блокировке — повторная попытка через 30 минут.

5.3. Последовательность цикла

  ┌─────────────────────────────────────────────────────────────────────────┐
  │ Фаза         │ Действие                     │ Длительность              │
  ├─────────────────────────────────────────────────────────────────────────┤
  │ kOzoneStart  │ Проверка условий запуска      │ < 1 такта                 │
  │ kOzoneActive │ Генерация озона (реле вкл.)   │ 15 минут (900 с)          │
  │ kOzoneHold   │ Пауза (озон оседает)          │ 2 часа (7200 с)           │
  │ kOzoneVent   │ Проветривание (вентилятор)    │ 15 минут или до мороза    │
  └─────────────────────────────────────────────────────────────────────────┘

  Внимание: во время работы озонатора вентилятор принудительно выключен.
  После завершения цикл возвращается в режим kAutoClimate.

5.4. Аварийная остановка (kOzoneAbort)

  При переходе в kOzoneAbort: немедленное выключение озонатора и вентилятора,
  возврат в kAutoClimate.


6. КОНЕЧНЫЙ АВТОМАТ (FSM)
================================================================================

  Состояния системы:

  ┌────────────────────────────────────────────────────────────────────────┐
  │ Состояние     │ Описание                                               │
  ├────────────────────────────────────────────────────────────────────────┤
  │ kIdle         │ Начальное состояние после сброса                       │
  │ kAutoClimate  │ Автоматический климат-контроль (основной режим)        │
  │ kOzoneStart   │ Проверка условий перед запуском озонирования           │
  │ kOzoneActive  │ Активная генерация озона                               │
  │ kOzoneHold    │ Пауза для оседания озона                               │
  │ kOzoneVent    │ Проветривание погреба после озонирования               │
  │ kOzoneAbort   │ Аварийная отмена цикла озонирования                    │
  │ kManualFan    │ Ручное управление вентилятором                         │
  │ kManualOzone  │ Ручное управление озонатором                           │
  │ kErrorState   │ Аварийный останов при критической ошибке               │
  └────────────────────────────────────────────────────────────────────────┘

  Переход в kErrorState немедленно выключает оба реле (entry-action в ChangeState).
  Выход из kErrorState — только через ручной сброс ошибки в меню.
  Автосброс ошибок климата (kTempTooLow, kCondensationRisk): при устранении
  физической причины ошибка сбрасывается автоматически.


7. КОНТРОЛЬ ОШИБОК И ДИАГНОСТИКА
================================================================================

7.1. Коды ошибок

  ┌───────────────────────────────────────────────────────────────────────┐
  │ Код               │ Условие возникновения                             │
  ├───────────────────────────────────────────────────────────────────────┤
  │ kSensorBmeFail    │ BME280 не отвечает или даёт невалидные данные     │
  │ kSensorHtuFail    │ HTU21D не отвечает или даёт невалидные данные     │
  │ kSensorDsFail     │ DS18B20 отключён или не инициализирован           │
  │ kRtcFail          │ DS3231 не отвечает или время сбито                │
  │ kTempMismatch     │ Расхождение BME280 и DS18B20 более 2.0 °C        │
  │ kCondensationRisk │ Точка росы внутри >= T_in − 0.5 °C               │
  │ kTempTooLow       │ T_in <= 2.0 °C (риск заморозки)                  │
  └───────────────────────────────────────────────────────────────────────┘

7.2. Восстановление датчиков

  При сбое датчика контроллер выполняет до 3 попыток переинициализации
  с интервалом 60 секунд.

  При зависании шины I2C выполняется программный сброс:
    1. Отключение TWI-периферии
    2. Задержка 10 мс
    3. Генерация 9 тактов SCL (bit-bang) для освобождения SDA
    4. Повторная инициализация Wire + таймаут 3000 мкс
    5. Переинициализация всех I2C-устройств

7.3. Сторожевой таймер (WDT)

  Аппаратный WDT с таймаутом 8 секунд. При зависании основного цикла
  контроллер перезагружается автоматически. WDT сбрасывается в начале
  каждой итерации loop().


8. ХРАНЕНИЕ ДАННЫХ В EEPROM
================================================================================

  Сохраняемые параметры (структура PersistentData):
    - Целевая температура (float)
    - Целевая влажность (float)
    - Калибровочные поправки для 5 каналов (float × 5)
    - Статистика наработки: uptime, fan, ozone (uint32_t × 3)

  Схема записи:
    - Wear-leveling: 10 слотов с ротацией (продление ресурса EEPROM)
    - Верификация: CRC16 для каждого слота
    - При чтении: выбирается последний слот с валидным CRC
    - Автосохранение: каждые 30 минут при работе
    - Немедленное сохранение: при изменении настроек через меню
    - Защита: static_assert гарантирует что слоты не выходят за 1 КБ


9. ПОЛЬЗОВАТЕЛЬСКИЙ ИНТЕРФЕЙС
================================================================================

9.1. Главный экран

  Строка 0:  IN  <T>C <RH>%  <индикатор_реле>
  Строка 1:  OUT <T>C <RH>%  <время>

  При недоступном датчике вместо значений выводится "---".
  Индикатор реле: F=вентилятор, Z=озонатор, пробел=выключено.

9.2. Структура меню

  │ Раздел   │ Содержимое                                           │
  ├─────────────────────────────────────────────────────────────────┤

  │          │ Показатели датчика OUT (T, RH, AH, Td)              │
  ├─────────────────────────────────────────────────────────────────┤
  │ SETTINGS │ Целевая температура (2.0 ... 15.0 °C, шаг 0.1)      │
  │          │ Целевая влажность (50 ... 95 %, шаг 1.0)            │
  ├─────────────────────────────────────────────────────────────────┤
  │ MANUAL   │ Ручной запуск вентилятора (30 минут)                 │
  │          │ Ручной запуск озонатора  (15 минут)                  │
  ├─────────────────────────────────────────────────────────────────┤
  │ STATS    │ Наработка: uptime / fan / ozone (часы или дни)       │
  │          │ Сброс статистики                                     │
  ├─────────────────────────────────────────────────────────────────┤
  │ ERRORS   │ Текущий код ошибки + время последней ошибки          │
  │          │ Сброс ошибки (ручной)                                │
  ├─────────────────────────────────────────────────────────────────┤
  │ SERVICE  │ Калибровка BME280: T offset, RH offset               │
  │          │ Калибровка HTU21D: T offset, RH offset               │
  │          │ Калибровка DS18B20: T offset                         │
  └─────────────────────────────────────────────────────────────────┘

9.3. Управление кнопками

  ┌───────────────────────────────────────────────────────────────────┐
  │ Кнопка        │ Короткое нажатие      │ Длинное нажатие           │
  ├───────────────────────────────────────────────────────────────────┤
  │ ВВЕРХ         │ Навигация вверх       │ Навигация по разделам     │
  │ ВНИЗ          │ Навигация вниз        │ Навигация по разделам     │
  │ МЕНЮ          │ Вход в подменю/выбор  │ Выход из подменю          │
  └───────────────────────────────────────────────────────────────────┘

  Автовыключение подсветки: через 30 секунд бездействия.
  Нажатие любой кнопки при выключенной подсветке только включает её.

9.4. Отображение статистики

  При значениях счётчиков менее 1000 часов — вывод в часах (h).
  При значениях 1000 часов и более — вывод в днях (d) для предотвращения
  переполнения 16-символьной строки ЖК-дисплея.


10. КАЛИБРОВКА ДАТЧИКОВ
================================================================================

  Для каждого датчика хранятся калибровочные поправки (offset):
    - BME280: ΔT (°C), ΔRH (%)
    - HTU21D: ΔT (°C), ΔRH (%)
    - DS18B20: ΔT (°C)

  Поправки применяются к отфильтрованным данным по формуле:
    T_calibrated = T_filtered + ΔT

  Диапазон поправок: −5.0 ... +5.0 (шаг 0.1).
  Поправки сохраняются в EEPROM.


11. ПАРАМЕТРЫ НАДЁЖНОСТИ
================================================================================

  11.1. Защита от переполнения millis()
    Все таймеры используют паттерн (now − timer >= interval), корректно
    обрабатывающий переполнение uint32_t (~49.7 дней).

  11.2. Защита реле от частых переключений
    Вентилятор: минимальный интервал между переключениями 5 минут.
    Экстренное отключение игнорирует этот интервал (force=true).

  11.3. Стабилизация фильтров
    Сравнение показаний BME280 и DS18B20 (kTempMismatch) выполняется
    только после 3 циклов стабильных показаний обоих датчиков.

  11.4. Защита памяти
    static_assert на этапе компиляции гарантирует что размер EEPROM-слотов
    не превышает 1024 байт при изменении структуры PersistentData.

  11.5. Программный сброс I2C
    Bit-bang восстановление шины (9 тактов SCL) при обнаружении зависания.

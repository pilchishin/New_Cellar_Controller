# Система управления климатом в погребе

## Описание проекта

Система управления погребом представляет собой Arduino-устройство на базе Arduino Nano, предназначенное для автоматического контроля климата в подвале или погребе. Система использует различные датчики для мониторинга температуры, влажности и других параметров, а также управляет вентиляцией и озонированием для поддержания оптимальных условий хранения продуктов.

## Основные функции

### Климат-контроль
- Автоматическое управление вентиляцией для поддержания заданной температуры (4°C) и влажности (85%).
- Использование алгоритма сравнения абсолютной влажности внутри и снаружи помещения для эффективного проветривания.
- Защита от образования конденсата на основе расчета точки росы.
- Применение фильтров (медианный + EMA) для сглаживания показаний датчиков.

### Озонирование
- Автоматический цикл озонирования по расписанию (раз в неделю в 02:00).
- Трехфазный цикл: активное озонирование (15 мин) → пауза/дезинфекция (2 часа) → проветривание (15 мин).
- Проверка условий безопасности перед запуском (температура на улице > 0°C, отсутствие активности пользователя).
- Защита от повторных попыток при неблагоприятных условиях (ожидание 30 минут).

### Мониторинг и управление
- Отображение данных с датчиков на LCD-экране (16x2) с I2C интерфейсом.
- Развитое древовидное меню управления с использованием 3-х кнопок (Вверх, Вниз, Меню).
- Возможность ручного запуска вентиляции (30 мин) и озонирования (15 мин).
- Просмотр статистики наработки устройств (uptime, fan, ozone).
- Система калибровки всех датчиков через сервисное меню.

### Безопасность и надежность
- Контроль критических параметров (заморозки, риск конденсации, расхождение показаний датчиков).
- Аппаратная защита с использованием сторожевого таймера (**Watchdog**) на 8 секунд.
- Алгоритм **активного восстановления I2C-шины** (bit-bang SCL) при обнаружении зависаний.
- Сохранение настроек и статистики в EEPROM с использованием алгоритма **Wear Leveling** (выравнивание износа) и контролем целостности по **CRC16**.

## Структура файлов

```
src/
├── main.cpp                (Основной цикл, инициализация, WDT)
├── config.h                (Пины, константы, уставки)
├── Types.h                 (Enums, структуры данных)
├── MathUtils.h/cpp         (Климатические формулы и фильтры)
├── SensorManager.h/cpp     (Опрос и диагностика датчиков)
├── TimeManager.h/cpp       (RTC DS3231 и расписание)
├── RelayManager.h/cpp      (Управление нагрузками и защита двигателя)
├── AppEEPROM.h/cpp         (Wear-leveled хранилище настроек)
├── ButtonEngine.h/cpp      (Антидребезг и обработка нажатий)
├── DisplayUI.h/cpp         (Рендеринг интерфейса и метаданные меню)
├── UIModel.h/cpp           (Слой данных для отображения)
├── MenuNavigator.h/cpp     (Логика переходов по меню)
├── MenuDispatcher.h/cpp    (Маршрутизация событий кнопок)
├── MenuActions.h/cpp       (Исполнение команд меню)
└── Controller.h/cpp        (Главный FSM и бизнес-логика)
```

### Основные компоненты

#### Controller
Центральный модуль с конечным автоматом (FSM). Обрабатывает переходы между состояниями `kAutoClimate`, `kOzoneActive`, `kManualFan` и др. Обеспечивает связь между данными датчиков и исполнительными механизмами.

#### SensorManager
Управляет датчиками BME280 (внутри), HTU21D (улица) и DS18B20 (контроль). Реализует неблокирующее чтение, фильтрацию Median+EMA и проверку достоверности данных.

#### DisplayUI & Menu System
Разделенная архитектура интерфейса:
- **DisplayUI**: Рендеринг строк, управление подсветкой.
- **Menu System**: Логика навигации и обработки действий отделена от отрисовки, что позволяет экономить память за счет хранения структуры меню в `PROGMEM`.
- **UIModel**: Обеспечивает слабую связанность интерфейса и логики контроллера.

#### AppEEPROM
Реализует циклическую запись в 10 слотов EEPROM для продления срока службы памяти. Каждая запись защищена контрольной суммой CRC16.

## Требования к установке

### Аппаратные требования
- **Arduino Nano** (ATmega328P)
- Датчики: BME280, HTU21D, DS18B20
- RTC **DS3231**
- LCD **16x2** с I2C адаптером
- 3 кнопки (активный уровень - LOW)
- Твердотельные реле (SSR) для вентилятора и озонатора

### Зависимости
Проект использует следующие библиотеки:
- Adafruit BME280 Library (^2.3.0)
- Adafruit Unified Sensor (^1.1.15)
- Adafruit HTU21DF Library (^1.1.2)
- DallasTemperature (^4.0.5)
- OneWire (^2.3.8)
- RTClib (^2.1.4)
- LiquidCrystal_I2C (^1.1.4)

## Настройка и сборка

Проект разработан с использованием **PlatformIO**.

1. Клонируйте репозиторий.
2. Откройте проект в VS Code с установленным расширением PlatformIO.
3. Отредактируйте `src/config.h` при необходимости смены пинов или уставок.
4. Соберите проект: `pio run`
5. Загрузите прошивку: `pio run --target upload`

## Отладка
При включенном макросе `#define DEBUG` в `config.h` система выводит подробный лог работы (состояния FSM, ошибки датчиков, события меню) в Serial-порт на скорости 9600 бод.
*Примечание: для финальной сборки рекомендуется отключить DEBUG для экономии Flash-памяти.*
